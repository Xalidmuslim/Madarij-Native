# Conservative registry proposal

Reproduce from the repository with `python3 research/final-translation-collation/classify_narrations_conservative.py`. It reads both current corpus JSON files and REPORTED_SPEECH_CANDIDATES.jsonl, and writes CITATION_REGISTRY.jsonl and CITATION_REGISTRY_SUMMARY.json alongside the script. Input SHA256 values and counts are recorded in that summary.

Coverage: all 796 existing reported-speech/quoted-term candidates are retained; a fresh scan of current «…», “…” and straight double-quoted spans found no additional spans. All 1,083 current Arabic curly-brace spans in author paragraphs are added as Quran-convention candidates. Total: 1,879 rows. This covers all spans detected by these delimiters, not every actual narration in the books: undelimited reports and attribution across paragraph/page boundaries require human discovery. Overlapping/nested citations remain separate spans when separately delimited.

Each row retains the exact Arabic quote, full delimited span, Python Unicode code-point offsets, up to 400 preceding and 220 following characters, current paragraph hash, page attribution and deterministic rule evidence. All existing candidate offsets matched the current Arabic. Quran-reference candidates are copied from nearby brackets without claiming they refer to that particular span; several spans can share a later reference. Damaged/incomplete verses are preserved as-is.

Classification is deliberately TWO LEVELS: suggested_type is an automated suggestion; verified_type stays null. verification_status always says automatic_suggestion_only_not_source_verified. No source identity, Quran correctness, hadith grade, isnad, attribution, or printed-edition wording is verified by this process. hadith_grade always stays null, even where the book itself says صحيح. Source titles are technical_term candidates with quoted_source_title subtype, not prophetic reports. Explicit divine-report/athar wording without a safely established prophetic chain remains unresolved/divine_report_or_qudsi_candidate.

Rules use only literal local Arabic attribution markers: explicit prophetic attribution, selected explicit companion/predecessor names, Harawi/Manazil introductions, Israiliyat wording, and lexical/title introductions. These are suggestions, not authority: a preceding marker can belong to another nested quotation, and inherited speakers are not tracked. Salaf suggestions include generic predecessors and later named scholars in the local context, not a certified historical generation assignment. Unresolved is intentional. Human review should check the full paragraph plus boundaries, promote a verified_type only with a recorded reviewer and evidence, and keep conflicting source-attribution hypotheses visible.

The producer does not modify the application, Arabic source, original candidate inventory, or publication metadata. Its derived artifacts are committed as research data. It is not publication certification or visual collation with the 2019 scans.

Refinement: each row now includes source_mentions containing only literal nearby book-title/attribution-marker text with exact paragraph offsets. These are copied from the corpus, with source_field_status=`literal_corpus_mentions_only_not_primary_source_verified`. Each mention explicitly has primary_source_verified=false and link_to_quote=`unverified_nearby_context_only`. They are candidates from a bounded context, not bibliographic resolutions; generic words such as صحيح can still denote an assessment rather than a book. Human confirmation of both meaning and linkage is required. Quran references likewise remain nearby_reference_candidates, not verified references. Regeneration records current input hashes if translation integration has changed the corpus files.
